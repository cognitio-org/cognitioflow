# Phase 20 — The exam-hypothetical case trainer

Branch: `phase-20-case-trainer`. Depends on Phase 11 (the arena — the quiz Question shape and the "what
you missed" review path) and Phase 17 (the essay bank pattern). Migration number: **028**.

Settled with Matej in `~/reports/cf-casetrainer-decisions.md` (2026-10-12). This phase *extends* Phase 11
and Phase 17; it does not fork a second quiz path.

## What Matej asked for

> "MCQ that creates cases so you revise exam questions while doing MCQ."

A realistic **fact-pattern hypothetical** with embedded **MCQs that test the legal ISSUES in it**
(issue-spotting), grounded in the course material — so revising an MCQ is revising an exam-style problem.

## Decisions — settled

- **A "case" = a fact-pattern hypothetical + N MCQs on its issues.** Each MCQ reuses the Phase-11
  Question shape `{question, options[4], correct_index, explanation}`; the fact pattern is the new
  wrapper. Each explanation **teaches** (why right, why each wrong) and cites the material.
- **Both lengths, selectable.** A **short hypo** (~a paragraph, 3–5 MCQs) and a **full exam-length
  fact pattern** (longer, 5–12 MCQs). A `length` param on bank/next; `casetrainer.LENGTHS` holds the two.
- **New `/api/courses/{cid}/case/bank|next|answer`**, mirroring the oral/essay bank pattern. `/quiz` is
  not overloaded. Banked per course and week.
- **Generated by the CHEAP/bulk tier** (`pick_model("cards", …)`, `task="case"`): the local 7B in dev
  when `CF_LOCAL_TASKS` names `case`, else the configured cheap cloud tier (Kernal `gemini-2.5-flash`
  in prod). Banking a question is not the analytical call.
- **Grounded + abstain.** The fact pattern and MCQs come ONLY from the course's ticked files (via
  `build_context`, honouring the `[OUTSIDE FILES]` rule). `CASE_GROUNDING_RULES` tells the writer to
  use only the material, never invent law, and write **fewer — or none —** and flag `thin` when the
  source is too thin (`CF_CASE_MIN_SOURCE_CHARS`, default 600). `casetrainer.normalise_case` drops any
  malformed MCQ (bad `correct_index`, non-distinct or ≠4 options) rather than show it.
- **Distractors via student-error modelling.** The three wrong options use the same guidance as the
  quiz's `card_distractors` machinery, factored into `DISTRACTOR_GUIDANCE` and shared by `/quiz` and the
  case writer: "plausible to a student who half-knows the material … never a paraphrase of the right
  answer".
- **"What you missed" via FSRS — no second scheduler.** A missed MCQ becomes a card (front = the MCQ,
  back = the correct option, `source = case:<id>`) rated `Again` through the existing
  `review()` → `schedule.next_review()` path; a later correct answer on the same MCQ rates that same
  card `Good`. An MCQ answered right the first time creates nothing — the deck tracks what you *missed*,
  as Phase 11 decided.

## Files

- `migrations/028_case_trainer.sql` — `case_hypos` (the fact pattern) + `case_hypo_mcqs` (the MCQs, in
  the Phase-11 shape; `options` is JSONB). Named `case_hypos`, not `cases`, because the course domain
  already uses "case" for case *law* (`GET /api/courses/{cid}/cases` is the case-law index from notes).
- `casetrainer.py` — the pure shapes/validation/choose, beside `oral.py` and `essay.py`.
- `run.py` — `/case/bank`, `/case/next`, `/case/answer`; `CASE_GROUNDING_RULES`; `DISTRACTOR_GUIDANCE`
  (extracted from `quiz()`, byte-identical). No model SDK imported; all calls through `ask_model`.
- `static/index.html`, `static/app.js`, `static/book.css` — the Cases surface (new nav item + screen),
  reusing the quiz option vocabulary. Every existing `id`/`data-` hook kept; tokens only; no framework.
- `tests/test_case_trainer.py`.

## How to see it

1. `docker compose up -d && make dev`, open `http://localhost:8000`, pick a course with ticked files.
2. **Cases** in the sidebar → choose a length (Short hypo / Full exam) → **Build cases from my files**.
3. Read the fact pattern, answer an MCQ: the correct option lights green, your wrong one red, and the
   explanation that teaches lands immediately below.
4. A miss: open **Recall** → the MCQ is now a card due today (the "what you missed" link points there).

## Definition of done

- [ ] A case bank is generated per course and week from ticked files only; `[OUTSIDE FILES]` labels
      anything beyond them, and the writer abstains (fewer/none, `thin` flagged) on a thin source.
- [ ] Both lengths are selectable and stored; `/case/next` can filter by length.
- [ ] Each MCQ is the Phase-11 shape: four distinct options, a correct index in range, a teaching
      explanation. A malformed MCQ is dropped, never shown.
- [ ] `/case/next` serves the fact pattern and its MCQs **without** the answer or explanation.
- [ ] `/case/answer` returns the correct option and explanation; a miss schedules a card `Again` via
      the one review path, a correct answer with no card behind it schedules nothing.
- [ ] Banking uses `pick_model("cards", …)` on the cheap tier and never `STRONG_MODEL`; a test asserts it.
- [ ] An empty/whitespace source is a 400 before any model call.
- [ ] The surface is keyboard-reachable with a visible focus ring; checked light + dark, 1440px + 1190px.

## Deferred

- A second grounded distractor pass per MCQ with its own cache (like `card_distractors`), if the
  single-pass student-error distractors prove weak. Today they are generated inline with the stem.
- Escalating the writer to the main tier if the cheap tier's hypotheticals read thin. The hook is there
  (`model` override on the bank request); the default stays cheap.
